# seed

`make seed` loads the development fixture (`../../fixtures`) into the local database: the city, then its plans. Run `make migrate-up` first. Running it again replaces the fixture's rows with the fixture's.

It reads `DATABASE_URL` (`make seed` points it at the local Supabase database) and **refuses any database that isn't on this machine**, before it connects and without printing the URL: the host must be `localhost` or a loopback address, with no `host=` override in the query. The one way past that is `--hosted-dev` (`make seed-dev`), which also needs `SEED_DEV_PROJECT_REF`, the dev project's ref: the URL's host must be `db.<ref>.supabase.co`, or its user `postgres.<ref>` on a Supabase pooler, so a URL for another project is refused with the flag set. That alone can't stop someone passing production's own ref, so `--hosted-dev` also reads `current_setting('issho.environment', true)` on the target before writing anything and refuses unless it is exactly `dev`. The founder sets that once, on issho-dev only (`alter database postgres set issho.environment = 'dev'`), by hand: nothing in the repo sets it, and production never has it. The local path never reads the marker. The founder seeds once, after dev is migrated and marked; a worker never does. The production image doesn't build it. See `../../fixtures/README.md`.
