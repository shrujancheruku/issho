# seed

`make seed` loads the development fixture (`../../fixtures`) into the local database: the city, then its plans. Run `make migrate-up` first. Running it again puts the fixture's rows back: the city row is upserted to the fixture's values, and each plan is deleted and inserted again with the fixture's content. The city and the plans are written in one transaction.

**`--admit <email>`** (`make seed ADMIT=<email>`, `make seed-dev ADMIT=<email>`) also admits the account that signed in with that email, with no join link and nobody who brought it in: the Pilot's first member, the owner, so there are links to give ([People](../../../docs/spec/people.md#join-links)). The email is the operator's to type; the repo holds none, and the seed never prints it. The account must have signed in once already; if none has, the seed stops and writes nothing, since the fixture and the admission are one transaction and the same environment checks guard both. Running it again changes nothing. `cmd/cmd_test.go` proves it (`TestSeedAdmitsTheAccountNamedByTheFlag`, `TestSeedAdmitOfAnUnknownEmailWritesNothingAndDoesNotEchoIt`).

It reads `DATABASE_URL` (`make seed` points it at the local Supabase database) and **refuses any database that isn't on this machine**, before it connects and without printing the URL: the host must be `localhost` or a loopback address, with no `host=` override in the query. The one way past that is `--hosted-dev` (`make seed-dev`), which also needs `SEED_DEV_PROJECT_REF`, the dev project's ref: the host must be `db.<ref>.supabase.co`, or the user `postgres.<ref>` on a Supabase pooler, so a URL for another project is refused with the flag set. That is checked on the connection pgx would actually make (host, user and any fallback hosts, after the URL and `PG*` environment are applied), not on the URL's text, so a `?user=` in the query can't change which project it names. That alone can't stop someone passing production's own ref, so `--hosted-dev` also reads the database's *stored* setting (`pg_db_role_setting`, this database, no particular role, which any role can read) and refuses unless it holds `issho.environment=dev` exactly. It does not use `current_setting`: a session can set that for itself, with `?options=-c issho.environment=dev`, `PGOPTIONS` or `SET`, which would make production read as dev. For the same reason `--hosted-dev` refuses, before it connects, a URL or `PG*` environment that sets any session parameter (`options`, `application_name`, …). The marker check runs in the transaction that writes, on its connection, before its first write. The founder sets that once, on issho-dev only (`alter database postgres set issho.environment = 'dev'`), by hand: nothing in the repo sets it, and production never has it. The local path never reads the marker. The founder seeds once, after dev is migrated and marked; a worker never does. The production image doesn't build it. See `../../fixtures/README.md`.
