# rpc

The API's ConnectRPC surface. `NewHandler(Config)` serves every service behind the access interceptor (`access.go`), which enforces the `access` option each RPC declares in its proto. `Config` carries the build's version, the `Authenticator`, the accounts (`People`), the cities and plans (`Cities`, `Plans`) and the logger.

**Tokens and accounts (`authenticator.go`, `account.go`).** `NewAuthenticator(verifier)` is the `Authenticator` that trusts what `people.Verifier` verifies: the caller's id, email and second step. `Identity.Email` is the caller's own and is never logged. `AccountService` is mounted only when `Config.People` is set (a process with no database serves the public RPCs only). `GetAccount` is a member RPC that returns the caller's own account, making it on the first call, and has no way to name another's.

**Plans (`plan.go`).** `PlanService` has two public RPCs, `ListPlans` and `GetPlan`: anyone, with no token, reads a city's plans and one plan with its stops and legs. The caller's display language is a request field (`en` or `vi`, empty is English; another is `invalid_argument`) since a public call has no account to take it from. A city that isn't listed and a plan that doesn't exist (or whose id couldn't be one) are `not_found`, never an empty list entry or an empty plan. The service is mounted only when both `Config.Cities` and `Config.Plans` are set. The currency and time zone on a plan are the city's, joined here from `cities`.

**`GET /up`.** The deploy's liveness probe: kamal-proxy polls it and sends a new container traffic only once it answers 200. It is not an RPC, so it is outside the access interceptor and the request log (it would add a line per poll). It checks nothing but that the process answers: a database check would take the API out of service for a database blip the proxy can't fix.

**Request log (`requestlog.go`).** With `Config.Log` set, the handler logs one `request` line per request: `route` (the RPC's procedure, `/issho.v1.HealthService/Check`, or `unmatched` for a path no service owns), `status`, `duration_ms` (read from `Config.Clock`) and `account` (the caller's ID) when the caller sent a good token. The line is built from those fields only, never from the request, so no IP address, email, body, header or token reaches it. A handler that panics is recovered there, before net/http's own panic log (which prints the caller's address and the panic's value) can see it: the request gets its line with status 500, and the panic's value is not logged. `Config.Clock` is required when `Log` is set; with `Log` nil nothing is logged.

Tests go through HTTP: `access_test.go` (the interceptor), `health_test.go` (the health check and `/up`), `requestlog_test.go` (the request line, including that an email in the body and a forwarded-for header never appear), `account_test.go` (accounts through HTTP with real Postgres and a fake Supabase Auth: the first call makes the account, a forged, foreign-key or expired token is refused, each caller sees only their own, and no other RPC's response carries an email), `plan_test.go` (the plan RPCs through HTTP on the fixture city with no authenticator at all: a list, one plan with its fields and legs, the text in each language, not-found, an unlisted city, an unoffered language, and no service without a database), `panic_test.go` (a panicking request, through the real `serve.HTTP`, logs one line with the route and 500 and nothing reaches the standard logger). `rpcauth/` is the check behind `make rpc-auth`.
