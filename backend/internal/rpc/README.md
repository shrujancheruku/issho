# rpc

The API's ConnectRPC surface. `NewHandler(Config)` serves every service behind the access interceptor (`access.go`), which enforces the `access` option each RPC declares in its proto. `Config` carries the build's version, the `Authenticator`, the accounts (`People`), the cities and plans (`Cities`, `Plans`), the signups to them (`Signups`) and the logger.

**Tokens and accounts (`authenticator.go`, `account.go`).** `NewAuthenticator(verifier)` is the `Authenticator` that trusts what `people.Verifier` verifies: the caller's id, email and second step. `Identity.Email` is the caller's own and is never logged. `AccountService` is mounted only when `Config.People` is set (a process with no database serves the public RPCs only). `GetAccount` is a member RPC that returns the caller's own account, making it on the first call, and has no way to name another's.

**Profile (`profile.go`).** `ProfileService`, mounted with `AccountService`, has `GetProfile` (the caller's own, or an empty response while there is none) and `SaveProfile` (makes it on the first call with the date of birth, changes it on later ones). Neither takes an account id. A refusal the app acts on carries a `ProfileProblem` error detail: `UNDER_AGE` and `WOMEN_ONLY_NOT_AVAILABLE` on `SaveProfile` (both `invalid_argument`), and `PROFILE_REQUIRED` (`failed_precondition`) from `rpc.RequireProfile(ctx, people, accountID)`, which every RPC that needs a profile (a signup) calls first. A caller with a token but no account yet gets `failed_precondition` and no detail: make the account (`GetAccount`) first.

**Plans (`plan.go`).** `PlanService` has two public RPCs, `ListPlans` and `GetPlan`: anyone, with no token, reads a city's plans and one plan with its stops and legs. The caller's display language is a request field (`en` or `vi`, empty is English; another is `invalid_argument`) since a public call has no account to take it from. A city that isn't listed and a plan that doesn't exist (or whose id couldn't be one) are `not_found`, never an empty list entry or an empty plan. A closed city's plans are kept but not shown (`docs/spec/cities.md`): `ListPlans` returns none and `GetPlan` on one of them is `not_found` with the same message as a plan that doesn't exist. The service is mounted only when both `Config.Cities` and `Config.Plans` are set. The currency and time zone on a plan are the city's, joined here from `cities`.

**Signups (`signup.go`).** `SignupService` (member), mounted when `Config.People` and `Config.Signups` are set: `SignUp` (makes the caller's signup to a plan with its ticks, or replaces the ticks of the one they have), `WithdrawSignup` and `ListMySignups` (their own, each with its hear-by day). None takes an account id, so none can name another person. `SignUp` calls `RequireProfile` first, so a caller with no profile is `failed_precondition` with `ProfileProblem` `PROFILE_REQUIRED`. A tick the plan refuses is `invalid_argument` with a `SignupProblem` detail (`TICK_TOO_SOON`, `TICK_PART_NOT_ALLOWED` or `TICK_TOO_FAR`); a plan that isn't there, or in a closed city, is `not_found`. When `Config.Signups` is set, `ListPlans` and `GetPlan` also fill each plan's `signed_up`, how many are signed up and never who.

**`GET /up`.** The deploy's liveness probe: kamal-proxy polls it and sends a new container traffic only once it answers 200. It is not an RPC, so it is outside the access interceptor and the request log (it would add a line per poll). It checks nothing but that the process answers: a database check would take the API out of service for a database blip the proxy can't fix.

**Request log (`requestlog.go`).** With `Config.Log` set, the handler logs one `request` line per request: `route` (the RPC's procedure, `/issho.v1.HealthService/Check`, or `unmatched` for a path no service owns), `status`, `duration_ms` (read from `Config.Clock`) and `account` (the caller's ID) when the caller sent a good token. The line is built from those fields only, never from the request, so no IP address, email, body, header or token reaches it. A handler that panics is recovered there, before net/http's own panic log (which prints the caller's address and the panic's value) can see it: the request gets its line with status 500, and the panic's value is not logged. `Config.Clock` is required when `Log` is set; with `Log` nil nothing is logged.

Tests go through HTTP: `access_test.go` (the interceptor), `health_test.go` (the health check and `/up`), `requestlog_test.go` (the request line, including that an email in the body and a forwarded-for header never appear), `profile_test.go` (the profile RPCs through HTTP: save and read back, under 18 and the women-only setting refused with their reasons, an invalid answer saves nothing, `RequireProfile`'s refusal and its detail, each caller's own profile, and that no other RPC returns a profile nor can name a person), `account_test.go` (accounts through HTTP with real Postgres and a fake Supabase Auth: the first call makes the account, a forged, foreign-key or expired token is refused, each caller sees only their own, and no other RPC's response carries an email), `plan_test.go` (the plan RPCs through HTTP on the fixture city with no authenticator at all: a list, one plan with its fields and legs, the text in each language, not-found, an unlisted city, a closed city's plans not shown, an unoffered language, and no service without a database), `signup_test.go` (the signup RPCs through HTTP with real accounts: a caller with no profile is refused with `PROFILE_REQUIRED` and nothing is kept, a member signs up to both plans and reads them back with the hear-by day, changes and withdraws, each refused tick carries its reason and saves nothing, a missing plan is not found, no token is refused, and a plan's `signed_up` counts people without naming one), `panic_test.go` (a panicking request, through the real `serve.HTTP`, logs one line with the route and 500 and nothing reaches the standard logger). `rpcauth/` is the check behind `make rpc-auth`.
